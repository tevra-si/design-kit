# Workflow example

## Brief

"Redesign the Today page of a personal task app. Users mostly open it on a laptop but sometimes on a phone. Prioritize adding and completing tasks quickly; don't change the stack."

## 1. Research

Read the current route/components and identify the add/complete task actions, platforms, breakpoints, validation and existing states. Do not invent metrics or habits without evidence. Output the current state, constraints, open questions and confidence per `design-research`.

## 2. Direction

Draft concepts with concrete trade-offs, for example a task-focused daily workspace versus a planner dashboard with heavier navigation. Choose by the goal, update the context, then run the validator.

## 3. Build

Read the context and existing components; update only the Today flow without changing routing/stack. Ensure the form is keyboard-accessible, focus is visible, errors sit next to inputs, and empty/success/loading states fit.

## 4. Review

Capture desktop and mobile and record the viewports. Score the six rubric dimensions; fix BLOCK/MAJOR first, recapture and update the findings. If the browser/screenshots are unavailable, mark visual review as unverified.
